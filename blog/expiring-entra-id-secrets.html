Vanhenevat Entra ID -sovellussalaisuudet: löydä ne ennen kuin tuotanto kaatuu

Klassinen perjantai-illan tragedia: rajapinta heittää virhettä AADSTS7000222: The provided client secret keys for app are expired. Näin hallitset elinkaaren automatisoidusti.

Entra ID (entinen Azure AD) -sovellusten rekisteröinnit (App Registrations) ovat modernien pilvipalveluiden, integraatioiden ja CI/CD-putkien selkäranka. Sovellukselle luodaan usein salasana (Client Secret) 6–24 kuukauden voimassaololla.

Ongelma? Kun salaisuus lopulta vanhenee, se tapahtuu ilman että kukaan muistaa asiaa. Kehittäjä on saattanut vaihtaa työpaikkaa, ja dokumentaatio puuttuu.

Paras ratkaisu: Poista salaisuudet kokonaan

Ennen kuin ryhdytään rakentamaan valvontaa vanheneville salaisuuksille, kannattaa pohtia voidaanko salaisuuksista luopua kokonaan:

  • Managed Identity: Azure-palveluiden välillä (kuten Azure App Service, Azure Function, VM) ei tarvita salasanoja lainkaan. Hyödynnä aina User-Assigned tai System-Assigned Managed Identityä.
  • Workload Identity Federation (OIDC): GitHub Actionsissa ja GitLabissa ei tarvitse säilöä pitkäikäisiä client secretejä. Käytä sen sijaan OIDC-federoitua todennusta, jolloin GitHub saa lyhytikäisen tokenin suoraan Entra ID:ltä.

Miten valvoa olemassa olevia salaisuuksia?

Kaikkia salaisuuksia ei kuitenkaan aina voi poistaa, etenkin jos kyseessä on kolmannen osapuolen integraatio tai ulkoinen SaaS-palvelu. Tällöin valvonta on välttämätöntä.

Alla on yksinkertainen PowerShell-skripti, joka käyttää Microsoft Graph PowerShell -moduulia listaamaan kaikki 30 päivän sisällä vanhenevat salaisuudet ja sertifikaatit: 

# Yhdistä Microsoft Graphiin tarvittavilla oikeuksilla
Connect-MgGraph -Scopes "Application.Read.All"

$warningThresholdDays = 30
$now = Get-Date

$apps = Get-MgApplication -All
$expiringSecrets = @()

foreach ($app in $apps) {
    # Tarkista salasanat (Client Secrets)
    foreach ($password in $app.PasswordCredentials) {
        if ($password.EndDateTime -and $password.EndDateTime -lt $now.AddDays($warningThresholdDays)) {
            $expiringSecrets += [PSCustomObject]@{
                AppName       = $app.DisplayName
                AppId         = $app.AppId
                Type          = "PasswordSecret"
                Hint          = $password.Hint
                Expires       = $password.EndDateTime
                DaysRemaining = [math]::Round(($password.EndDateTime - $now).TotalDays)
            }
        }
    }
}

# Tulosta hälytykset
$expiringSecrets | Sort-Object DaysRemaining | Format-Table

Automaattiset hälytykset Teamsiin tai Slackiin

Skriptin voi ajaa helposti kerran viikossa esimerkiksi Azure Automation Accountin runbookina tai ajastettuna Azure Functionina. Jos vanhenevia salaisuuksia löytyy alle 30 päivän aikarajalla, skripti lähettää ilmoituksen tiimin Teams- tai Slack-kanavalle tai tekee automaattisesti tuki-tiketin.
